redo.toml configuration

Choosing the interpreter that runs each do-file in redo-msh.

By default, redo-msh runs every do-file with msh (mshell), the cross-platform shell language it was designed around. That keeps builds working identically on Linux, macOS, and Windows without shebang handling.

To drop redo-msh onto an existing project whose do-files are written for another interpreter — sh -e, bash, python3, … — commit a redo.toml at the project root that maps do-files to the command used to run them.

No shebangs. redo-msh never inspects a #! line. The interpreter mapping is always explicit and lives in version control, so a checkout builds the same way for everyone regardless of file permissions or platform quirks.

Where it lives

A single file named redo.toml at the project root — the same directory that holds .redom/. Put it under version control.

Not inside .redom/. That directory is git-ignored (it holds the SQLite database and locks). Configuration that should be shared must sit at the root, beside it.

If redo.toml is absent, every do-file runs with the built-in default, ["msh"].

How a do-file is invoked

The resolved value is an argv prefix. redo-msh appends the do-file path and the three standard redo arguments to it: 

<interpreter...>  <dofile>  $1  $2  $3
ArgumentMeaning
$1the target being built
$2the target with its matched extension removed (for default.*.do)
$3a temporary output path; write here (or to stdout), never to $1

So command = ["sh", "-e"] runs sh -e <dofile> $1 $2 $3, and the default ["msh"] runs msh <dofile> $1 $2 $3.

Schema

Two kinds of tables, both optional:

  • [interpreter] — settings shared across all platforms.
  • [platform.<name>] — overrides for one platform: linux, wsl, windows, or macos.

Each such table accepts the same two keys:

KeyTypeMeaning
default array of strings The interpreter argv prefix used when no rule matches.
rule array of tables Ordered list of { match, command } pairs; the first whose match glob matches the do-file wins.

A rule is written as a TOML array-of-tables, [[interpreter.rule]] or [[platform.<name>.rule]], with:

KeyTypeMeaning
matchstringA glob tested against the do-file (see below).
commandarray of stringsThe interpreter argv prefix for matching do-files.

Resolution order

For a do-file at root-relative path P on the current platform, redo-msh takes the first of these that produces a command:

  1. a matching rule in the platform table,
  2. the platform table's default,
  3. a matching rule in the shared [interpreter] table,
  4. the shared [interpreter].default,
  5. the built-in ["msh"].
WSL. Under WSL, redo-msh uses [platform.wsl] if present; otherwise it falls back to [platform.linux] (WSL is Linux) before dropping to the shared and built-in layers. WSL is detected via the WSL_DISTRO_NAME / WSL_INTEROP environment variables or a microsoft/wsl marker in the kernel release.

Glob matching

PatternBehavior
no /matched against the do-file's basename, so it matches anywhere in the tree.
contains /matched against the full root-relative path.
*matches any run of characters except /.
?matches exactly one character except /.

Patterns are anchored: the whole text must match. Neither * nor ? crosses a directory separator.

PatternMatchesDoes not match
*.doapp.do, sub/a.b.doapp.dof
*.py.dobuild.py.dobuild.do
deploy/*.dodeploy/ship.dodeploy/nested/ship.do
The match is on the do-file, not the target. A target main.o built by default.o.do is matched by patterns against default.o.do.

Examples

A whole project ported to POSIX sh

[platform.linux]
default = ["sh", "-e"]

[platform.macos]
default = ["sh", "-e"]

[platform.wsl]
default = ["sh", "-e"]

[platform.windows]
default = ["msh"]          # no sh on native Windows; keep mshell there

Mostly sh, with a few Python recipes

[interpreter]
default = ["sh", "-e"]

[[interpreter.rule]]
match   = "*.py.do"        # any do-file ending in .py.do, anywhere
command = ["python3"]

A directory that builds with bash

[interpreter]
default = ["msh"]

[[interpreter.rule]]
match   = "deploy/*.do"    # only do-files directly under deploy/
command = ["bash", "-euo", "pipefail"]
Empty command. A command = [] (or empty default) is treated as unset and falls back to the built-in ["msh"] rather than producing an un-runnable interpreter.

The redo command family

redo-msh ships the standard commands — redo, redo-ifchange, redo-ifcreate, redo-always, redo-stamp — as individual executables beside the redo-msh binary, and prepends its own directory to each do-file's PATH. Existing do-files that call redo-ifchange directly work unchanged, with no system-wide install required.

redo-stamp is a compatibility no-op: it drains its standard input and exits. redo-msh content-hashes every committed output by default, so the change-suppression a stamp provides is already the baseline behavior.
